# GEO Writing Check（GEO 写作检查）

写完一篇文章，检查它是否便于 AI 搜索理解和引用：开头有没有直接回答、主体写没写清楚、说法有没有出处、段落单独拿出来能不能看懂。每一项给出情况、改法和具体位置。

纯本地运行，不联网，不调用 AI，不上传任何笔记内容。

> An Obsidian plugin that checks whether a Chinese article is easy for AI search engines to understand and cite: answer-first leads, clear entities, sourced claims, self-contained passages, explicit dates. Rule-based and fully offline. The checks target Chinese prose, so the interface is in Chinese.

## 检查什么

共 17 项，分五类。

| 类别 | 检查项 | 看什么 |
| --- | --- | --- |
| 直接回答 | 开头直接回答 | 第一段是否直接给出结论，而不是背景铺垫或反问 |
| | 小节先给结论 | 每个小标题下的第一段是否先回答 |
| | 标题说清主题 | 标题长度；设了关键词时，是否出现在标题、第一段和小标题 |
| 主体明确 | 主体名称出现 | 品牌或机构名称是否写出，是否出现得足够早 |
| | 段落不以指代开头 | 以“它”“这个”“该产品”开头的段落，单独被引用时会失去所指 |
| | 自称带上名称 | “本公司”“我司”“小编”无法被归到具体主体 |
| 证据可核 | 具体数字与事实 | 是否有年份、数量、比例等可核对的信息 |
| | 说法有出处 | “数据显示”“研究表明”同句是否给出来源 |
| | 少用空泛形容 | “领先的”“一站式”“匠心”等不提供信息的词 |
| | 引用来源 | 较长的文章是否引用了外部资料或文件 |
| 便于摘录 | 段落长度、句子长度 | 过长的段落和句子难以被完整摘录 |
| | 标题层级 | 是否跳级；较长的文章是否有小标题 |
| | 问句式小标题、列表或表格 | 仅作提示，不计分 |
| 时效清楚 | 日期信息 | 属性或正文里是否有明确日期 |
| | 不用相对时间 | “最近”“今年”“去年”离开发布日期后无法判断所指 |

## 怎么用

1. 安装并启用后，打开一篇文章。
2. 点击左侧图标，或运行命令“打开检查面板”，查看分数和每一项的结果。
3. 点击面板里的位置跳到原文。编辑器里需要修改的位置有紫色虚线，鼠标停留显示改法。
4. 在 **设置 → GEO Writing Check** 里填写主体名称、开关检查项、调整字数阈值。

### 用到的笔记属性

```yaml
---
title: 南昌VI设计怎么选公司
主关键词: 南昌VI设计
品牌: 某某品牌设计
发布日期: 2026-09-01
GEO检查: false
---
```

- `title`：没有时用一级标题，再没有用文件名。
- `主关键词`：有值时检查关键词位置。
- `品牌`：这一篇的主体名称，优先于设置里的全局名称。
- `发布日期`：有值即视为有日期。
- `GEO检查: false`：关闭这一篇的检查。

属性名都可以在设置里改，默认同时识别常见的英文写法，如 `primary_keyword`、`brand`、`date`、`published_at`。

### 分数怎么算

每个计分项通过得满分、可改进得一半、需修改不得分，按权重加总成 0 到 100 分。85 分以上为“便于引用”，65 到 84 分为“基本可用”。“提示”类检查项和已关闭的检查项不计分。

## 局限

- 分数只反映文章的结构和写法，**不代表会被收录、引用或推荐**。AI 搜索是否引用一篇内容，还取决于站点权威度、是否可抓取、内容是否独到等本插件看不到的因素。
- 检查基于规则，不理解语义。它能发现“第一段是铺垫”，不能判断“回答得对不对”。
- 不要为了分数硬凑：没有可靠数字就不要编，没有步骤就不必加列表。不适用的检查项可以在设置里关掉。
- 正文少于 300 字的笔记不检查。

## 安装

在 Obsidian 的 **设置 → 第三方插件 → 浏览** 中搜索 “GEO Writing Check”。

手动安装：从 Releases 下载 `main.js`、`manifest.json`、`styles.css`，放入 `<库>/.obsidian/plugins/geo-writing-check/`，重启 Obsidian 后启用。
